按地区、医院、科室勾选功能

各地区、各医院、各科室对随访的要求不同。系统的功能全部做成可勾选的模块：首次进入时依次选择地区、医院、科室，系统按“同地区、同类医院、同科室最常用”的原则推荐一套配置并默认勾选。医生不了解时直接采用推荐，了解后再增减；没有勾选的功能不会出现在首页和菜单。下面可以直接试一试，首页数字和推荐来源均为演示。

四级配置，逐级继承

层级谁来配置配置什么规则

“最常用配置”怎么来

  1. 平台运营端汇总各医院的功能配置，只统计勾选了哪些功能、用了哪个模板，不涉及任何患者数据。
  2. 按“地区 × 医院类型 × 科室”计算采用最多的配置组合。
  3. 推荐顺序：本院同科室 → 本省同类医院 → 全国同类医院 → 专家默认模板；样本不足时自动退回下一级。
  4. 平台上线初期没有统计数据，先用临床专家按指南编制的默认模板；接入医院越多，推荐越贴近当地习惯。
  • 之后可在“医院管理后台 → 功能配置中心”随时增减，需审批的功能走申请流程。
  • 关闭功能不删除数据，重新开启后可继续使用。
  • 模板升级时医院先看差异再决定是否更新，不覆盖科室自己的修改。

随访闭环：只有异常和未响应才需要人工

出院即入组，到期自动推送；结果正常自动归档，异常分级预警给医生处置，未响应转人工补访。全部结果汇总到质控与满意度分析，再反过来优化随访方案和模板。

正常：自动归档评分和数据在阈值内，结果写入患者档案，到期自动进入下一个随访节点，不占用医护时间。
异常：分级预警红色预警即时推送责任医生手机，限时处置；超时自动升级给上级医生或科主任，处置结果必须留痕。
未响应：人工补访微信和短信超时未填写，转电话或智能外呼补访；多次联系不上进入失访管理，按多位联系人继续补访。
评价与改进满意度、投诉、随访率、再入院等指标汇总到管理驾驶舱，用于质控抽检、绩效考核和优化随访方案。

总体架构：配置与模板引擎决定每家医院看到什么

七个使用入口共用一套业务应用和能力中台。配置与模板引擎按“地区 → 医院 → 科室 → 个人”逐级合成功能开关，决定每个人的首页和菜单。患者数据留在医院本地，模板中心只同步配置。
